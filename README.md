# 지방소득세 담당 부서 찾기

여러 지자체의 개인·법인 지방소득세 담당 부서를 공식 홈페이지에서 찾아 공문 수신처로 정리하는 로컬 프로그램입니다. 첫 버전은 검색 API와 규칙 기반 본문 분석을 사용합니다. AI API와 별도 패키지 설치는 필요하지 않습니다.

## 실행

Python 3.10 이상이 필요합니다. 이 폴더의 `start.cmd`를 더블클릭하면 서버와 브라우저를 엽니다. 또는 터미널에서 다음을 실행합니다.

```powershell
python app.py --open
```

주소는 `http://127.0.0.1:8765`입니다. 실행 창을 닫으면 프로그램도 종료됩니다. 포트를 바꾸려면 `python app.py --port 8766 --open`을 사용하세요.

## 사용 흐름

1. `.xlsx` 엑셀을 업로드하고 시트, 제목 행, 지자체 열을 선택합니다. 시·도와 시·군·구가 분리돼 있으면 시·도 열도 선택합니다. 제목이 없는 시트는 제목 행을 0으로 설정합니다.
2. 조회 목록을 확인한 뒤 담당 부서 조회를 누릅니다. 한 번에 최대 100개이며, 같은 입력 이름은 한 번만 조회합니다. CSV/TSV와 여러 줄 붙여넣기도 지원합니다.
3. 결과 행을 선택하면 담당 업무 후보, 전화번호, 업무안내·조직도 근거를 볼 수 있습니다. 개인·법인·특별징수 담당이 다르면 각 항목을 비교하세요.
4. 공식 기관명, 국, 부서, 근거 URL을 확인하고 수신처로 저장합니다. 담당 부서를 수동으로 보완할 수도 있습니다.
5. 확인한 수신처만 복사할 수 있습니다. CSV 저장에는 미확인 후보도 상태와 함께 포함하지만, 미확인 행의 공문 수신처는 비워 둡니다. Excel에서 CSV를 열어 활용하세요.

업로드 파일은 디스크에 저장하지 않습니다. 선택한 지자체 이름과 공식 URL만 조회에 사용합니다. 수식 셀은 Excel에서 마지막으로 저장한 계산값을 읽으며, 병합 셀의 아래쪽 빈칸을 자동으로 채우지는 않습니다. 암호화 파일과 `.xls`는 지원하지 않으므로 `.xlsx`로 다시 저장하세요. 최대 10MB, 10,000행, 150열까지 읽습니다.

## 필요한 API

**행정안전부_행정표준코드_기관코드 API**의 일반 인증키를 지원합니다. 프로그램의 **API 설정 → 행정안전부 기관코드 API**에서 입력하고 **저장 및 연결 확인**을 누르세요. Decoding 키를 권장하며 Encoding 키도 처리합니다. 행정안전부 기관코드 `1741000`을 조회해 실제 인증과 응답을 확인합니다. 연결 확인에 실패해도 입력한 키는 저장되어 있으며 오류 안내에 따라 수정할 수 있습니다.

- 신청·문서: https://www.data.go.kr/data/15077870/openapi.do
- 부서명, 기관코드와 상위기관코드로 세무 관련 조직을 찾습니다. 상위 국은 코드 관계가 확인되는 경우만 표시합니다.
- 기관코드에는 담당업무가 없으므로 이 API만으로 찾은 결과는 **담당업무 미확인**입니다. 재무과·세무1과·세무2과 등이 반환되어도 첫 번째 부서를 담당 부서로 표시하거나 자동 선택하지 않습니다. 조직 후보는 별도 목록으로 보여 줍니다.
- API 자료와 홈페이지의 상위 국이 다르면 국을 비우고 상충 사실을 표시합니다. 같은 이름의 부서가 여러 조직에 있으면 코드와 전체 기관명을 별도로 보관합니다.
- CSV에는 기관코드와 전체 기관명, 자료 URL도 포함합니다. 인증키가 들어간 API 호출 URL은 결과나 CSV에 저장하지 않습니다.

기관코드와 함께 공식 홈페이지의 담당업무를 자동 검색하려면 **네이버 검색 API**의 **Client ID와 Client Secret**을 추가할 수 있습니다. 공식 업무안내 URL을 입력해 조회하는 방법도 지원합니다.

- 등록: https://developers.naver.com/apps/#/register
- 공식 웹문서 검색 문서: https://developers.naver.com/docs/serviceapi/search/web/web.md
- 애플리케이션 이름 예: `지방소득세 부서 찾기`
- 사용 API에서 `검색`을 선택합니다. 지역 업체 검색이 아니라 웹문서 검색을 사용합니다.
- 개발자센터의 서비스 환경 입력란은 해당 화면 안내를 따르세요. 이 프로그램의 로컬 주소는 `http://127.0.0.1:8765`입니다.
- 발급한 두 값은 프로그램의 **API 설정 → 네이버 웹문서 검색 API**에 직접 입력합니다. 채팅에 키를 붙여넣지 마세요.

값은 이 폴더의 `.env.local`에 저장되고 API 응답이나 화면 조회에 다시 노출하지 않습니다. 두 API의 설정은 함께 유지됩니다. 환경변수 `PUBLIC_DATA_SERVICE_KEY`, `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`도 지원하며, 환경변수가 설정되어 있으면 저장한 파일보다 우선합니다. 화면의 ‘설정됨’은 키 입력 여부입니다. 기관코드 API는 저장 직후 연결을 확인하고, 네이버 API는 첫 조회에서 인증을 확인합니다.

2026-10-03 확인한 네이버 공식 문서의 검색 API 호출 한도는 하루 25,000회입니다. 현재 코드는 지자체마다 검색 요청을 2회 합니다. 공식 사이트 페이지 조회는 이 검색 호출 수와 별개입니다. 실제 이용 조건과 한도는 발급 당시 공식 문서를 확인하세요.

공식 조직도나 업무안내 URL을 알고 있으면 파일의 URL 열을 선택하거나 상세 화면의 ‘이 URL로 조회’를 사용해 API 없이 읽을 수 있습니다. 서구와 인천 부평구는 검색 API 없이 공식 조직도에서 각 과의 직원 업무표를 따라가 조회합니다. 국·과 답을 고정하지 않으며, 공식 홈페이지 주소와 명칭 별칭만 등록되어 있습니다.

## 설계와 확인 기준

`엑셀 → 지자체 식별 → 공식 페이지 검색 → 업무표 분석 → 조직도 연결 → 사용자 확인 → 수신처 저장`

- `서구`, `중구` 등 동명이 있는 이름은 시·도를 요청합니다. 다른 지자체 자료가 섞이지 않도록 페이지의 기관명과 입력 지역을 대조합니다.
- 검색 요약만으로 담당 부서를 확정하지 않습니다. 공식 페이지 본문에 지방소득세 업무가 있으면 업무 후보, 기관코드에서만 찾으면 담당업무 미확인 조직 후보로 제시합니다.
- 국·과는 조직도의 중첩된 관계 또는 API의 상위기관 코드가 확인되는 경우 연결합니다. 관계가 불분명하거나 상위 국이 상충하면 비워 둡니다. 국이 없는 조직과 추출 실패를 자동으로 구분하지는 않습니다.
- 연락처는 같은 업무 행에서 추출하고, 개인·법인 담당을 별도로 보여 줍니다.
- 자동 결과는 후보입니다. 지방소득세 담당이라도 세입 이체 담당이 아닐 수 있어 업무를 확인한 후 저장하도록 합니다.
- 화면의 대표 부서와 상세 화면의 기본 선택에는 공식 업무안내에서 지방소득세 업무가 확인된 항목만 사용합니다. 기관코드에만 있는 조직은 CSV의 담당 부서·상위 국·전화번호를 비워 두고, 마지막 ‘조직 후보 목록(담당업무 미확인)’ 열에 보관합니다. 이 기준은 이전에 저장한 미확인 조회 결과에도 적용합니다. 직접 확인해 저장한 수신처는 사용자가 선택한 값을 유지합니다.
- 조회 시각과 사용자 확인 시각을 저장합니다. 조회 시각은 페이지를 읽은 시점이며 홈페이지 정보 자체의 개정일은 아닙니다. 이전 저장 결과를 최신 자료로 취급하지 않습니다.
- 공식 도메인(`*.go.kr`, `*.gov.kr`, 광역 지자체 도메인)만 자동 조회하며 내부망 URL은 거부합니다. 웹에서 가져온 스크립트는 실행하지 않습니다.
- 한 번에 한 조회 작업을 처리해 지자체 사이트 요청을 제한합니다. 중지하면 현재 지자체 처리가 끝난 뒤 남은 조회를 멈춥니다.

## 첫 버전의 범위와 다음 개선

현재는 HTML 업무표와 조직도 분석을 지원합니다. 이미지 조직도, PDF/HWP 첨부자료, CAPTCHA/접속 차단, 사이트마다 다른 동적 직원 검색은 수동 확인이 필요할 수 있습니다. 서구의 별도 직원 업무표 호출과 부평구의 ‘과 > 팀’ 제목 및 표 구조를 지원하며, 모든 지자체의 동적 페이지를 지원하는 것은 아닙니다. 네이버가 페이지를 검색하지 못하거나 공식 주소를 바꾼 곳도 검토 대상으로 남깁니다.

2026-10-06 부평구 사례를 조사한 결과 기관코드 API가 `재무과 → 세무1과 → 세무2과` 순서로 조직을 반환했으나, 기존 화면·CSV가 동일 점수의 첫 항목을 대표 부서로 사용한 문제가 있었습니다. API는 업무 담당 부서를 추천한 것이 아닙니다. 현재는 [부평구 공식 조직도](https://www.icbp.go.kr/main/introduction/guidance/organization.jsp)의 부서 링크와 [직원 업무표](https://www.icbp.go.kr/main/organization/organizationInfoList.do?orgno0=1&orgno1=129)를 읽어 업무 근거를 찾습니다. 다른 지자체도 업무안내 URL 또는 네이버 검색이 연결되어야 기관코드 목록에서 실제 담당 부서를 구분할 수 있습니다.

기관별 홈페이지 구조는 달라 전국 자동 추출률을 아직 측정하지 않았습니다. 먼저 실제 대상 20~30개 지자체를 조회해 실패 유형을 모은 뒤 자주 요청하는 지자체의 어댑터와 공식 홈페이지 목록을 추가하는 것이 다음 단계입니다. 이미지/PDF 때문에 누락이 많으면 출처를 유지하는 AI 추출을 선택적으로 추가할 수 있습니다. 이 단계에서 별도 AI API 필요성을 판단하면 됩니다.

`data/confirmed.json`에는 확인한 수신처가, `data/last-session.json`에는 마지막 완료·중지 결과가 저장됩니다. 수신처 형식은 `기관명(담당 부서)`이며, 전자문서 시스템의 실제 기관 코드나 수신 가능 여부를 검증하지 않습니다. 국은 별도 열로 보관합니다. 전자문서 발송이나 이체 실행 기능은 포함하지 않습니다.
